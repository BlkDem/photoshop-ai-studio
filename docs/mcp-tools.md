# MCP tools

> Generated by `node scripts/generate-tool-docs.mjs` from
> `shared/src/photoshop/operations.ts`. Do not edit by hand — that registry is the
> single source of truth for the MCP server, the planner prompt, the Studio Tools
> panel and the safety flags.

**Endpoint** `POST http://127.0.0.1:${MCP_PORT}/mcp` — Streamable HTTP, stateless.
**Naming** every tool is `photoshop.<operation>`. Dots are explicitly allowed by the
MCP tools specification.

## Before you plan: `get_capabilities`

`photoshop.get_capabilities` reports what the connected Photoshop will actually
perform, and it is worth calling before any plan that depends on a feature
outside the everyday set. It separates:

- `api` — the entry point exists in the live DOM;
- `usable` — this plugin has performed it on this build and watched it take
  effect;
- `note` — why not, when there is something to say.

The distinction is the whole point. `Layer.translate` *exists* and does nothing;
`placeEvent` exists and refuses every file the plugin can write; `crop` is
refused outright. A tool surface planned from the API reference is a tool surface
full of silent no-ops.

It is non-destructive and answers with no document open.

## Conventions

These hold for all 30 tools:

- **Coordinates** are absolute document pixels. Origin is the canvas top-left, y grows
  downward.
- **Layer addressing** takes exactly one of `layerId` (preferred — stable across
  reordering) or `layerName` (convenient; an ambiguous name is an error, never a guess).
- **`documentId`** defaults to `"active"` — the document the user is looking at.
- **Paths** must resolve inside `WORKSPACE_ROOT`; anything else is `PATH_NOT_ALLOWED`.
- **Results** are `{ success: true, data }` or `{ success: false, error }`, and the
  payload is validated against the tool’s declared result schema on both sides.

### Result shape

```json
{ "success": true, "data": { "id": 3, "name": "Title", "type": "text" } }
```

```json
{
  "success": false,
  "error": {
    "code": "LAYER_NOT_FOUND",
    "message": "Layer \"Logo\" was not found",
    "recoverable": true,
    "details": { "available": ["Title", "Subtitle"] }
  }
}
```

`recoverable` is the field the repair loop reads. `true` means re-planning may
plausibly succeed; `false` means stop and tell the user.

### Expectations

Every mutating tool has post-conditions derived from its arguments — see
[architecture.md ADR-007](architecture.md#adr-007--expectations-are-derived-not-trusted).
A plan may add its own expectations; it cannot remove a derived one. Read-only tools
have none, and a plan with no checkable operations reports "no checks" rather than
claiming success.

| Expectation kind | Checks |
| --- | --- |
| `layer_exists` / `layer_absent` | a layer matching the selector exists / does not |
| `layer_property` | `name`, `visible`, `opacity`, `x`, `y`, `width`, `height`, `parentId`, `type`, `blendMode`, `isLocked` |
| `layer_parent_named` | the layer's parent group has the given name (used when the group is addressed by name, so the new `parentId` is only knowable afterwards) |
| `document_property` | `name`, `width`, `height`, `resolution`, `colorMode`, `layerCount`, `path`, `saved` |
| `text_property` | `text`, `font`, `fontSize`, `color` — read back through `photoshop.get_text_layer` |
| `layer_count` | the document has exactly N layers |
| `file_exists` | the reported file exists (accepts the workspace-relative or the absolute path) |
| `custom` | deferred to the vision model; reported as `skipped` |

## Notes on specific tools

- `photoshop.get_document` returns metadata **and** the full flat layer list, so one
  round trip grounds the planner. `photoshop.get_document_info` skips the layer walk
  when only canvas geometry is needed.
- `photoshop.move_layer` accepts either `x`/`y` (absolute) or `dx`/`dy` (relative),
  never both.
- `photoshop.resize_canvas` changes the canvas **without scaling content**, matching
  Photoshop. Plans that need the artwork rescaled must include `resize_layer` /
  `set_text_font_size` steps.
- `photoshop.resize_layer` scales a text box but not its glyphs. Use
  `photoshop.set_text_font_size` for type.
- `photoshop.place_image` places a file as a smart object. The path must be inside the
  workspace; `fit` optionally scales the placed layer.
- `photoshop.export_document` dispatches on `format`; the three specific tools are
  thin, well-described aliases that a model picks more reliably.
- `photoshop.render_preview` returns a base64 PNG for the Studio preview pane. It
  writes to a temporary folder, never the workspace, and never mutates the document.

## Verification with `MCP Inspector`

```bash
npm run inspector
```

Use `http://127.0.0.1:3001/mcp` for a direct connection, or `http://localhost:3000/mcp`
to go through the Studio dev proxy (same origin, no CORS). With `MOCK_PHOTOSHOP=true`
this is a complete, safe playground for exercising every tool.
